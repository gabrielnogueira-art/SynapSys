## Platform rules
- Scope the management brand's CSS tokens to central platform and platform-login routes on the document root so portaled controls share the theme without overriding EBD/customer branding.
- Reuse the supplied platform symbol through its asset pointer and a shared PlatformBrand component to keep platform header and login consistent.
- Supabase is the authoritative store for contracts, memberships and requests; browser storage is only an explicit legacy import source.
- Account credential changes use Supabase Auth on the existing user ID so roles and contract affiliations survive email changes.
- Non-EBD module data uses contract/module keyed Supabase records with RLS and revision-checked writes to avoid cross-contract access and concurrent overwrites.
- Friendly links resolve to immutable contract IDs before membership checks; public directory preferences are projected by protected triggers and IDs remain valid legacy links.
- Shared contract link helpers produce published portal/login URLs; address uniqueness is enforced in the database to prevent client-link ambiguity.
- Contract memberships are separate from EBD hierarchical roles; contract access never replaces existing congregation/class RLS.
- Public contract resolution exposes branding and enabled modules only; billing and user directories require authenticated scoped access.
- Client simulation changes presentation only and never grants permissions; database authorization uses the real authenticated identity.
- Public branding is projected into a separate read-only directory table; private-schema triggers synchronize it without exposing commercial fields.
- Linked ministry and contract branding synchronize bidirectionally through depth-guarded triggers so either editor updates the same identity.
- Real contract accounts are provisioned only through authenticated administrative edge functions; church managers additionally receive the linked ministry role.
- User-affiliation getters, has_role, headquarters/regional deletion checks and congregation-structure management checks accept only the caller's auth.uid(); verified service-role calls may evaluate another identity to preserve protected administrative workflows.
